# Carrito, compra, seguimiento y edición de productos

Esta actualización parte del proyecto original `Ameli-Seguridad-PROYECTO(2).zip`. Conserva `Ameli.Seguridad.sln`, los proyectos API/Web/Contracts, la autenticación, los perfiles, el chat y los estilos existentes.

## Abrir y actualizar en Visual Studio

1. Descomprime el ZIP y abre **`Ameli.Seguridad.sln`**.
2. Conserva tus secretos de usuario y la conexión SQL existente. Si es tu primera ejecución, sigue [INICIAR-EN-VISUAL-STUDIO.md](INICIAR-EN-VISUAL-STUDIO.md).
3. Inicia **Ameli.Api** y **Ameli.Web** con el perfil `https`, en ambiente `Development`, como en el original.
4. La API aplica automáticamente la migración **`20261117225723_GOLCommerce`**. No necesitas borrar ni recrear la base. Conserva también el `App_Data` de tu instalación anterior, que contiene las claves persistentes.
5. Abre **https://localhost:7240/ingresar** y usa tus cuentas habituales.

La solución mantiene .NET 10 y SQL Server. Si administras las migraciones por separado, `database/03-gol-commerce.sql` actualiza una base que ya tiene las seis migraciones del original, hasta `20261014012404_RecommendationFeedback`. Es idempotente y no sustituye la instalación inicial. No ejecutes el script y la inicialización automática simultáneamente.

## Dónde probar cada historia

| Historia | Pantalla y comportamiento |
| --- | --- |
| GOL-002 | En **Productos**, la ficha, el chat o Recomendados: elegir talla o confirmar compra sin talla publicada y agregar unidades. Actualiza el subtotal y total del carrito. Cero stock: **Producto agotado**. Exceso: **Existencias de artículo superadas**. |
| GOL-003 | En **Mi carrito** (`/carrito`): cambiar la cantidad y pulsar **Guardar cantidad**; eliminar con confirmación. Al quedar vacío aparece **Ir al catálogo**. Si baja el inventario, la línea se marca y el pago permanece bloqueado hasta confirmar una cantidad válida o eliminarla. |
| GOL-004 | En el mismo carrito: seleccionar una dirección de **Direcciones de entrega**, completar los cuatro datos de tarjeta de prueba y pulsar **Confirmar pedido**. Guarda número único, precios y dirección, descuenta existencias y presenta el resumen en Mis pedidos. |
| GOL-005 | En **Mis pedidos** (`/mis-pedidos`): ver pedidos propios actuales y anteriores, importes y seguimiento con fecha y hora. Si no hay pedidos: **No hay pedidos anteriores o en camino**. |
| GOL-011 | Como **Administrador**, abrir **Productos base** (`/administracion/catalogos/productos`) → **Editar producto**. Permite guardar nombre, categoría, proveedor, descripción, precio, costo, material, especie, tallas, stock mínimo, existencias, estado e imagen. |

En **Gestión de pedidos** (`/gestion/pedidos`), Administrador y Logística pueden registrar **En preparación**, **En camino** y **Entregado**. Para En camino y Entregado se requieren transportista y guía. La fecha se guarda en UTC y se presenta en la zona horaria del navegador.

Los cambios de producto se validan antes de aplicarse. Un formulario inválido mantiene lo escrito y señala los campos que deben corregirse. La auditoría conserva los valores anteriores y nuevos; un guardado sin cambios no genera una actualización. La versión del registro evita sobrescribir una edición o cambio de inventario reciente. Cambiar nombre, precio, tallas o dirección no modifica los pedidos confirmados.

## Pagos de demostración

**Esta entrega no cobra dinero.** El original no tenía un proveedor de pagos ni se suministraron credenciales. El formulario indica **Pago de prueba** y el adaptador local permite comprobar aprobación y rechazo en `Development` o `Testing`. En `Production` bloquea la confirmación hasta integrar una pasarela real mediante `IPaymentGateway`.

| Dato | Valor para probar |
| --- | --- |
| Tarjeta aprobada | `4242 4242 4242 4242` o `5555 5555 5555 4444` |
| Tarjeta rechazada | `4000 0000 0000 0002` |
| Fecha de caducidad | Una fecha futura en formato `MM/AA`, por ejemplo `12/39` |
| Nombre del titular | Un nombre de prueba |
| CVC | `123` |

Sin dirección se muestra **Dirección de envío no especificada**. El rechazo muestra **Pago rechazado, intenta con otra tarjeta**; registra el intento, conserva el carrito y no crea un pedido confirmado ni descuenta inventario. Reintentar una misma solicitud no duplica la compra. No se guardan número de tarjeta, CVC ni nombre del titular en las tablas o la auditoría.

## Descuentos e impuestos

No se indicaron porcentajes ni reglas comerciales. **Descuentos e impuestos quedan en 0%** por defecto. Se recalculan al agregar, modificar, eliminar y confirmar. En `src/Ameli.Api/appsettings.json`, sección `Commerce`, se pueden configurar `DiscountPercent` y `TaxPercent`, entre 0 y 100. El descuento se calcula sobre el subtotal; el impuesto sobre el importe después del descuento. Ambos se redondean a dos decimales y se copian al pedido confirmado. Reinicia la API después de cambiar esta configuración.

## Verificación realizada

- Solución compilada en **Release**, sin errores ni advertencias. Modelo EF comprobado sin cambios pendientes respecto de las migraciones incluidas.
- **117 pruebas de .NET aprobadas** con SQL Server real: incluye las pruebas anteriores y las historias GOL, concurrencia, reintentos, permisos y conservación de precios.
- **12 pruebas de JavaScript aprobadas** para agregar al carrito, validación de stock, importes y reintentos.
- Flujo de los formularios comprobado mediante DOM y solicitudes HTTPS reales entre Web y API: confirmación de stock, pago rechazado y aprobado de prueba, edición comercial con imagen, datos inválidos retenidos, acceso denegado y seguimiento completo.
- Migración comprobada sobre una base creada con el código original y un pedido ya enviado: conserva número, dirección e importe y agrega el historial disponible.

La verificación DOM no sustituye una revisión visual en un navegador: no se ejecutó una comprobación visual automatizada. Se conservan las hojas de estilo originales y se agregan estilos para los campos y el historial nuevos.

Los pedidos antiguos no tenían historial de transiciones. La migración recupera su fecha de creación y su estado más reciente con la fecha que ya existía; no inventa fechas intermedias. El nombre antiguo **Enviado** se presenta ahora como **En camino** y sigue aceptándose como alias en la API.

Para repetir las pruebas: en Visual Studio, **Prueba → Explorador de pruebas → Ejecutar todas** con LocalDB, o configura una conexión SQL de pruebas en `AMELI_TEST_SQL`. Las pruebas de integración crean y eliminan su propia base. Las pruebas JavaScript se ejecutan con `node --test tests/cart-ui.test.cjs`. El escenario opcional de navegador sigue en `tests/browser/assistant-e2e.spec.cjs` y ahora completa también la tarjeta de prueba.
